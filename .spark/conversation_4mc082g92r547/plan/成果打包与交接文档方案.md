# 成果打包下载 + 交接文档（Handoff）方案

## 目标与成功标准

- 拿到一份包含全部源码（client / server / shared / 配置）的 zip 下载链接，浏览器可直接下载。
- zip 内附一份完整交接文档 `HANDOFF.md`；另提供单独的 handoff 文件链接，不解压也能阅读。
- 交接文档做到「新接手的人（或新 AI 会话）读完能直接继续开发」：功能清单、架构、数据模型、API、设计规范、业务规则、开发工作流、已验/未验项全覆盖。

## 实现方案

1. **写 `HANDOFF.md`（仓库根目录）**，内容结构：
   - 项目定位与核心机制（国策树 / 每日结算 / 递归回滚 / 冻结 / 喜报 / 图标系统）
   - 技术栈与目录结构（NestJS 单模块 `server/modules/rsip/` + React 单页 + Drizzle/Postgres 10 张表）
   - 数据库表与关键约束（rsip_policies.icon_key、tree_id、group_id、RLS 按 user_profile 隔离）
   - API 清单（前缀 api/rsip，17 个端点及用途）
   - 前端页面与组件地图（RsipPage 20 个组件 + DashboardPage + 共享 PolicyIcon 等）
   - 设计规范要点（冷静中性基调、amber 点亮、禁红色、文案原则、间距排版）
   - 关键业务规则（回滚语义、冻结/解冻重判、结算窗口、每日新增门槛、主动型 ≤3、里程碑阈值）
   - 开发工作流（改码 → commit_task 提交；DDL 走 lark-apps-db 通道 → gen:db-schema → 重读 schema.ts；发布走 +release-create）
   - 验证状态清单（已闭环验证的接口/E2E；未实测项：里程碑自动喜报未在真实数据触发、树重命名/归档未实操）
   - 已知限制与后续建议（单用户工具、无通知 push、数据为用户真实数据）
2. **提交 HANDOFF.md**（commit_task）——必须先提交，`+export` 只归档最后一次提交，不提交就不会进 zip。
3. **导出源码**：`lark-cli apps +export --app-id "$app_id" --output ./rsip-app-source.zip`，输出 zip 到沙箱工作目录。
4. **上传并生成下载链接**：
   - `+file-upload --file ./rsip-app-source.zip` → 拿到远端 path
   - `+file-sign --path <zip路径> --expires-in 2592000`（30 天，最长档）
   - HANDOFF.md 单独同样上传 + 签名，便于直接在线阅读
5. **回复用户**：两个下载链接 + 有效期说明 + handoff 要点摘要。

## 影响范围与风险

- 只新增 `HANDOFF.md` 一个文件并提交，不改任何业务代码，无功能影响。
- 导出的 zip 无 git 历史、无环境变量（`+export` 通道特性），会在 handoff 中说明。
- 下载链接为临时签名链接（30 天过期），过期后可重新上传生成。

## 验收标准

- zip 下载链接浏览器可打开且文件完整（解压含 client/server/shared/HANDOFF.md）。
- HANDOFF.md 单独链接可读。
- 交接文档内容与当前实现一致（表结构、端点数、组件清单以代码为准）。

## 未决事项

无（链接有效期直接取最长 30 天，无需确认）。
